# java-racingcar-precourse

## 서비스 흐름
1. 어플리케이션이 AppConfig를 불러오고 불러온 AppConfig에서 컨트롤러를 얻어 호출하여 어플리케이션이 시작된다.
2. 컨트롤러는 뷰와 서비스를 조작하고 입력 뷰에서 데이터를 받아 서비스에게 전달하고 3개의 흐름으로 나뉘어진 서비스 로직을 호출한다.
3. 서비스 로직은 레파지토리 계층을 통해 상태를 기억하며 그 자체로는 무상태성이다.
4. start를 통해 각 도메인을 조작하여 처음 세팅을 마친 후 레파지토리에 정보를 저장한다.
5. getRoundResult를 통해 레파지토리의 정보를 불러와 경기를 진행하고 다시 save 한다.
6. getFinalWinners를 통해 최종 우승자를 반환한다.
7. 컨트롤러는 각각의 이 서비스들을 조합하여 서비스와 반복적으로 정보를 주고받는다.
8. 최종적으로 뷰로 결과가 완성되어 나온다.

## 다음과 같은 구조 채택 이유
사실, 서비스에서 한번에 로직을 처리해서 대량의 문자열이 담긴 output을 서비스에 전달해도 되었겠으나...  
시도 횟수에 따라 가변적인 길이를 가진 결과가 나온다는 점에서 저는 반복적인 로직을 수행한다는 점에서 게임의 상태를 기억하고 출력하는 방식을 채택해 보고 싶었습니다.  
이를 위해 presentation 계층을 구현해야만 했고, 레파지토리 계층을(실제 구조와는 많이 동떨어져 있지만) 구현해보고자 하는 새로운 목표로서 접근해 보았습니다.  
입력값의 유효성 검증은 parser부에서 진행해 주었고, 도메인 부에서 자기 자신의 값의 책임을 가지도록 유효성 검증을 어느 정도 분산시켰습니다.  
dto를 사용해서 래핑하여 전달하는 계층간 데이터 전송을 적용해 보았습니다.

## 기능 정의
### inputView:  
문자열을 입력받는데, 각 문자열은 쉼표(,)를 기준으로 구분되고, 구분되는 항목은 각각은 자동차의 이름을 의미한다.
템플릿 문자열을 출력 후 입력값을 입력받아 포장하여 반환한다.  
```bash
경주할 자동차 이름을 입력하세요.(이름은 쉼표(,) 기준으로 구분) # input_template
> pobi,woni,jun # input1
시도할 횟수는 몇 회인가요? # input_template
> 5 # input2
```
  
### outputView:  
리스트를 입력받는데, 각 리스트는 자동차의 이름과 해당 자동차가 이동한 거리를 포함한 raceStateResponse 리스트를 입력받는다.
해당 뷰는 리스폰스를 해체하여 각 자동차의 이름과 이동거리를 출력한다.

해체 포맷은 다음과 같이 구성된다.
``` bash
실행 결과 # output_template1
pobi : -
woni : 
jun : -

pobi : --
woni : -
jun : --

pobi : ---
woni : --
jun : ---

pobi : ----
woni : ---
jun : ----

pobi : -----
woni : ----
jun : -----


최종 우승자 : pobi, jun
```
### InputView:
- 사용자로부터 입력을 받는 기능을 담당한다.
- 템플릿을 출력하는 기능
- 자동차 이름 입력을 위한 템플릿 출력 및 입력값 받기
- 시도 횟수 입력을 위한 템플릿 출력 및 입력값 받기
- 입력값을 포장하여 반환하는 기능

### OutputView:
레이싱 게임의 결과를 출력하는 기능을 담당한다.
- 템플릿을 출력하는 기능
- 레이싱 게임의 각 라운드 결과를 출력하는 기능
- 최종 우승자를 출력하는 기능

### RacingCarController:
레이싱 게임의 전체 흐름을 제어하는 기능을 담당한다.
- 서비스, 뷰를 호출하여 뷰에서 입출력을 받고 전달하여 분할된 서비스 흐름을 통제.

### CarRacingService:
- 실제 비즈니스 로직을 담당하며, 4가지 기능을 가지고 있습니다.
- 도메인 모델을 통한 초기화 및 상태를 repository에 저장
- repository에서 상태를 로드하여 레이싱 게임 한 라운드를 진행하여 그 상태를 다시 repository에 저장
- repository에서 상태를 로드하여 승자 리스트를 반환
- controller의 반복 근거가 되는 게임 반복자 반환

### randomGenerator:
랜덤 숫자를 생성하는 기능을 담당한다.
- 0 이상 9 이하의 숫자를 랜덤으로 생성
- 문제 조건에 맞게 판단하여 boolean 값을 반환해주는 기능을 가진다.

### car:
자동차 엔티티로서 다음과 같은 속성과 기능을 가진다.
- 속성: 이름, 현재 위치
- 기능: 이동 기능
- 기능: 현재 위치 조회

### cars:
자동차 엔티티들을 관리하는 컬렉션 객체로서 다음과 같은 기능을 담당한다.
- 속성: 자동차 리스트
- 기능: 자동차 추가
- 기능: 자동차 이름 기반 자동차 객체 반환 기능
- 기능: 자동차 이름 기반 이동 (각 자동차의 이동 기능 호출)

### GameState:
레이싱 게임의 라운드를 나타내는 객체로서 다음과 같은 속성과 기능을 가진다.
- 속성: 현재 라운드 번호
- 기능: 라운드 번호 증가
- 기능: 남은 라운드 여부 조회

### InputParser  
사용자 입력값에 대한 파싱을 진행하는 객체로서 다음과 같은 기능을 가진다.  
- 입력값을 ,기호에 맞게 토크나이징 하여 List에 삽입후 리턴
- 입력값 검증 기능 포함
  
## 예외 처리
- 전부 IllegalArgumentException 으로 처리
- 자동차 이름이 빈 문자열이거나 공백만 있는 경우: "자동차 이름은 빈 칸일 수 없습니다."
- 자동차 이름이 10글자를 초과하는 경우: "자동차 이름은 10글자를 초과할 수 없습니다."
- 자동차 이름이 중복되는 경우: "자동차 이름은 중복될 수 없습니다."
- 자동차 이름과 , 사이 공백 허용 여부 : 허용
- 라운드 수 입력값이 null인 경우: "입력값은 null일 수 없습니다. 입력값을 정상적으로 입력해 주세요"
- 라운드 수가 숫자가 아닌 경우: "시도 횟수는 숫자여야 합니다."
- 라운드 수가 100회를 초과하는 경우 : "시도 횟수가 너무 큽니다. 100회 이하로 입력해주세요."
